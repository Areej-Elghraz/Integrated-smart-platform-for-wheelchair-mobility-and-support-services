Use Cases 

Intelligent Wheelchair Management System 

 

User Use Cases 

Control Wheelchair 

Actor 

User 

Goal 

Control the wheelchair movement through the application. 

Preconditions 

User is logged in and the wheelchair is connected. 

Main Flow 

The user opens the control screen. 

Selects a movement direction (Forward, Backward, Left, Right). 

The application sends the command to the wheelchair. 

The wheelchair receives and executes the command. 

The application confirms movement was applied. 

Alternative Flow 

If the wheelchair is disconnected, an error message appears. 

User is prompted to retry the connection. 

Postcondition 

Wheelchair moves in the selected direction. 

 

Send SOS Alert 

Actor 

User 

Goal 

Send an emergency alert during dangerous situations or abnormal health conditions. 

Preconditions 

User is logged in.  
User has at least one connected companion. 
Health sensors are connected and active. 

Main Flow 

1.  The user presses the SOS button manually 
OR 
     The system automatically detects abnormal sensor readings or fall       
     movement.  
2.  The system collects the current location and health sensor data.  
3.  Emergency alerts are sent to connected companions.  
4.  Emergency health status is also shared with connected doctors.  
5.  A confirmation notification is shown to the user.  

Alternative Flow 

If there is no internet connection, a no internet message appears. 

A local notification is stored to be sent when connection is restored. 

Postcondition 

All connected companions receive the SOS alert with location and health data. 
Connected doctors receive the user’s current health status and emergency condition.  

 

View Health Status 

Actor 

User 

Goal 

Monitor health condition using sensors. 

Preconditions 

User is logged in and health sensors are active. 

Main Flow 

The user opens the dashboard. 

The system retrieves live sensor data. 

User views heart rate, body temperature, and MPU status. 

User reviews health history and past alerts. 

Alternative Flow 

If sensor data is unavailable, a Sensor Disconnected warning is displayed. 

Postcondition 

User has a clear view of their current and historical health status. 

 

Explore & Manage Accessible Places 

Actor 

User 

Goal 

Explore accessible places and create personal categories and places through the application. 

Preconditions 

User is logged in and location services are enabled. 

Main Flow 

The user opens the accessible places section.  

The system displays available organizations.  

The user selects an organization.  

The system displays available buildings inside the selected organization.  

The user browses floors inside the building.  

The user views accessible places inside each floor.  

Accessibility information is displayed clearly for every place.  

The user can create personal categories.  

The user can add custom places inside personal categories.  

Personal categories and places are visible only to their creator and their companions. 

Alternative Flow 

- If no accessible places are available, an empty state appears. 

Postcondition 

The user can explore accessible locations easily. 
The user can create and manage personal categories and custom places privately.  

 

Navigate to Destination 

Actor 

User 

Goal 

Navigate to a selected destination using manual or autonomous mode. 

Preconditions 

User is logged in and wheelchair is connected. 

Main Flow 

1. The user selects a destination. 

2. The system displays available navigation modes. 

3. The user chooses manual or autonomous mode. 

4. Navigation starts successfully. 

Alternative Flow 

- If navigation fails, the user receives an error message. 

Postcondition 

The wheelchair navigates toward the selected destination. 

 

Companion Use Cases 

Send Companion Request 

Actor 

Companion 

Goal 

Request connection with a wheelchair user. 

Preconditions 

Companion is logged in and has a registered account. 

Main Flow 

The companion searches for the user by username or ID. 

Sends a companion connection request. 

The user receives a notification of the request. 

The user accepts or declines the request. 

Alternative Flow 

If the request is declined, the companion is notified and cannot access the user's dashboard. 

Postcondition 

If accepted, the companion is linked to the user and can monitor their status. 

 

Monitor User Status 

Actor 

Companion 

Goal 

Monitor the user's health and emergency status in real time. 

Preconditions 

Companion is connected and approved by the user. 

Main Flow 

The companion opens the monitoring dashboard. 

The system retrieves live sensor readings for the linked user. 

Companion views heart rate, temperature, and MPU data. 

Companion receives push notifications for emergency alerts. 

Alternative Flow 

If the user revokes access, the dashboard becomes unavailable and the companion is notified. 

Postcondition 

Companion stays informed about the user's health and safety in real time. 

 

 

 

 

 

 

 

 

 

 

 

Doctor Use Cases 

Accept Patient Request 

Actor 

Doctor 

Goal 

Accept or decline a patient follow request. 

Preconditions 

Doctor has a verified medical account on the system. 

Main Flow 

The doctor receives a follow request notification from a patient. 

Reviews the patient's basic profile information. 

Accepts or declines the request. 

Alternative Flow 

If declined, the patient is notified that the request was not accepted. 

Postcondition 

If accepted, the patient appears in the doctor's patient list and health data becomes accessible. 

 

Monitor Patients 

Actor 

Doctor 

Goal 

Track multiple patients' health status remotely. 

Preconditions 

Doctor is logged in and has at least one accepted patient. 

Main Flow 

The doctor opens the patients dashboard. 

Selects a specific patient from the list. 

Views heart rate, temperature, MPU status, alerts, and medical information. 

Receives emergency warnings for abnormal readings. 

Alternative Flow 

If abnormal sensor readings are detected, an emergency warning banner appears. 

Doctor can immediately contact the patient or companion. 

Postcondition 

Doctor has a comprehensive real-time overview of each patient's condition. 

 

 

 

 

 

 

Organization Use Cases 

Add Building 

Actor 

Organization 

Goal 

Add a new building to the accessibility map system. 

Preconditions 

Organization has a verified and approved account. 

Main Flow 

The organization opens the management dashboard. 

Navigates to Add Building. 

Enters building details (name, address, description). 

Saves the building successfully. 

Alternative Flow 

If required fields are missing, a validation error is shown. 

Postcondition 

Building is added to the system and visible to wheelchair users. 

 

Add Floors and Places 

Actor 

Organization 

Goal 

Add accessible locations inside buildings. 

Preconditions 

At least one building has been added by the organization. 

Main Flow 

The organization selects an existing building. 

Adds floors to the building. 

Adds places to each floor (Rooms, Elevators, Bathrooms, Halls). 

Includes accessibility information for each place. 

Alternative Flow 

If the floor number already exists, the system prompts to edit instead. 

Postcondition 

Floors and places are saved and displayed in the accessibility map. 

 

Manage Accessibility Information 

Actor 

Organization 

Goal 

Help wheelchair users navigate places more easily. 

Preconditions 

Organization has existing buildings and places in the system. 

Main Flow 

The organization opens a specific place's details. 

Edits accessibility information. 

Updates the accessibility status. 

Saves changes successfully. 

Alternative Flow 

If the save fails due to a network error, the system retries and notifies the user. 

Postcondition 

Updated accessibility information is immediately available to all wheelchair users.
